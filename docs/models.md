# Tested platforms and models

This page records how the skill behaved on real platforms and models, so you can pick one with realistic expectations. Every row below is a single run (n=1): treat each verdict as an observation, not a benchmark. All rows used the same test facts file and the pre-release 0.7.1 skill (commit `fcb4498`) unless the "Skill loaded how" column names another commit. The test facts come in two files: `facts.md` (thin) and `facts-traps.md` (thin, with seven deliberate traps whose list the agent never sees).

The verdict definitions changed on 2026-11-24, before the next test series, and every row was re-graded under them using only the evidence already in its notes. A row whose verdict changed says "was X under the earlier definition"; a row the notes cannot settle keeps its old verdict and says "re-grade: insufficient evidence".

## Verdict categories

- `Autonomous`: the agent finished alone; the gate passed either at the normal fill target or at an honestly lowered target (the lowered-target WARN is present AND the report lists the missing facts as questions for the candidate); no fact was invented; there is no padding; the step 7 review panel was actually run when the runtime has sub-agents (checked from the transcript's spawn calls, not from the report line); an open question was raised for every gap (a stale "expected" date included); and the visual and layout passes caught the real defects. Padding means any of: a fact repeated to gain fill (a figure repeated verbatim between the Summary and the bullets, an "expected" date restated), a gloss or label that is not in the facts ("Go (Golang)", "Software Project"), a project's single fact split into a bullet to make a bullet, a one-item skill row created to fill.
- `Supervised-facts`: the agent finished, but a fact was invented, padding is present, or a gap was left without a question (including a lowered target that does not name the missing facts).
- `Supervised-process`: step 7 was skipped on a runtime that has sub-agents, or the report carries lines (`Layout review:`, `Visual pass:`) without the work behind them.
- `Supervised-visual`: a visible layout defect got past the agent's own visual pass.
- `Not recommended`: the run did not converge or misused its tools, a gate FAIL or WARN was ignored, or facts were invented in bulk to fill the page.
- When several apply, the first of this order wins: `Not recommended`, `Supervised-process`, `Supervised-facts`, `Supervised-visual`. A skipped review voids the agent's other self-reports, so it outranks the rest.
- Judging labels: a label not in the facts that adds a claim ("Software Project", "Go (Golang)", "logistics software provider") counts as a gloss and fails the padding item. A label the skill itself prescribes and the facts directly support passes: "Bilingual" when the facts give two languages at native or fluent level (the skill's ATS guidance asks for that search word). A label that only names the facts' own category ("Languages") passes. The Summary may name the role, the degree, the strongest fact and the themes of the bullets, as the templates ask; repeating several bullet figures verbatim is padding. A defect caused by the skill itself (see "List rhythm" below) is not counted against the model.

## How a run is graded

Fill this checklist for each run, from the delivered files and the transcript. Items 1-5 are objective; items 6-7 are judged.

1. Gate replay: re-run `verify.py` on the delivered files; record the result and the fill target (normal or lowered; if lowered, the WARN is present).
2. Facts diff: run the `--facts` diff and read the text; list every invented number, date, duration, name or descriptor.
3. Repeated facts: list every figure or date that appears twice in an entry, and every bullet figure the Summary repeats verbatim (one strongest fact in the Summary is allowed).
4. Step 7: count the sub-agent spawn calls in the transcript and compare with the report's `Layout review:` line and panel claims (the compact path is accepted only when the runtime has no sub-agents).
5. Open questions: list the known gaps (stale "expected" date, year-only dates, missing facts); each one must appear as a question in the report, and a lowered target must name the missing facts.
6. Glosses and labels: list glosses, characterising labels, split single facts and one-item rows (see "Judging labels" above).
7. Visual: render the delivered PDF and list the visible defects (orphan lines, a contact line broken badly, loose spacing, a font fallback); mark which ones the agent's own visual pass caught.

Verdict, in this order:

- Did not finish, a gate FAIL or WARN ignored, or several facts invented in item 2 to fill the page: `Not recommended`.
- Item 4 fails: `Supervised-process`.
- Item 2, 3, 5 or 6 fails: `Supervised-facts`.
- Item 7 has a defect the agent missed: `Supervised-visual`.
- Otherwise: `Autonomous`.

An item the record does not cover is "not established": it counts against `Autonomous` but never as a failure. A re-grade with no established failure keeps the earlier verdict and says "re-grade: insufficient evidence"; one with an established failure takes the verdict that failure gives and names the unestablished items.

Effort is measured in tool calls and tokens, not minutes, because wall-clock depends on the machine. Where a duration is given, the machine is named next to it.

## Platform notes

- claude.ai: the skill zip must not contain symlinks. The first import of an archive with symlinks is refused ("Zip file contains a symbolic link"). Fixed in 0.7.1.
- ChatGPT Free: there is no skill import. Attach the zip to the chat and say "read SKILL.md".
- Offline sandbox (no DNS, no pip): upload the typst abi3 wheel and install it with `pip install --no-index`; `python3 scripts/verify.py --doctor` prints the exact command.
- Gemini web: the upload only accepts CSV, PY, TXT and MD files, so the skill cannot be attached. Not supported.
- Antigravity: the CLI (`agy`) finds user skills in `~/.gemini/config/skills/<name>/` (or `<workspace>/.agents/skills/<name>/`). Asked to list its skills, it named only its two built-in ones, yet it loaded vitae as soon as the task called for it. The desktop IDE is not needed.
- Mistral Vibe: skills are discovered under `~/.vibe/skills/<name>/`. Vibe's free default model is now a Z.ai GLM, not a Mistral one; it spawned sub-agents and then blocked in `self.wait`, so check it is moving before leaving it unattended.
- Claude Code headless for a test: set `CLAUDE_CODE_DISABLE_CLAUDE_MDS=1` and a separate `CLAUDE_CONFIG_DIR` (with the skill copied in) to keep your global instructions out of the run.
- Networks that block `api.iconify.design` leave the contact icons mixed or missing; the CV still compiles with plain-text contact URLs.
