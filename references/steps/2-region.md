# Step 2 — Pick region and language

2. **Pick region and language.** Infer a default from the source material — city/country in the header, phone country code, language and spelling variant, posting URLs — state it and confirm; never silently decide. The *target job market* always overrides where the candidate lives (a Montréal candidate applying to London jobs gets UK conventions). Load [`references/regional.md`](../regional.md) (router: file list + universal rules; each market file opens with "At a glance"), then ONLY the target market's file in `references/regional/` (e.g. [`north-america.md`](../regional/north-america.md), [`france.md`](../regional/france.md)) — don't load the other markets. When the TARGET market is Québec (a Québec employer or posting; a Québec address alone does not make it the target), also read [`references/regional/quebec.md`](../regional/quebec.md) on top of `north-america.md`; [`regional/quebec-outbound.md`](../regional/quebec-outbound.md) is read, on top of the target market's file, only when the candidate holds Québec credentials (DEC, AEC, DEP, Québec university degree, Québec order membership) and targets ANY market other than Québec; no other case loads it; the symmetric case (European credentials or CV habits, target USA/Canada/Québec) loads [`regional/europe-to-north-america.md`](../regional/europe-to-north-america.md) on top of `north-america.md`. Apply the language and spelling of the *job market*, not the user's chat language. If the market has no file, do not infer from training data — verify with a current source or ask, and label the assumption in the deliverable.
