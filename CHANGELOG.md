# Changelog

Format follows [Keep a Changelog](https://keepachangelog.com/). Newest first. Versions are the `version:` in `SKILL.md`; hashes point to the release commit.

## Unreleased

- Docs: both READMEs match the current repo (uv-first requirements pointing to the PEP 723 headers, review-record gate, PDF/UA + PDF/A, declared WARNs, upstream fonts, models and extractors links).
- Docs: the fact sheet is `facts.md` everywhere (README, academic mode, letter template, reviews); the academic example data is `templates/academic/academic.example.toml` and cites `facts.md#…`.
- Verify: two WARN checks driven by explicit declarations. `section(.., summary: true)` marks the Summary; a figure it states (with its unit; ranges as one figure; years and month/year dates excluded) that a bullet outside it repeats is a WARN. `entry`/`job(.., expected: true)` marks an anticipated date; a latest year before the current year is a WARN. Every template passes `summary: true` on its Summary/Profile section. No word of any language is read: an undeclared or unbounded Summary gives no finding.
- Fonts: installation advice is OS-portable. Provenance is `upstream: <source>` or `GF (...)`; the distro package names (`local:`, `GF · Linux: <package>`, the Debian/Fedora table) are gone, `references/fonts.md` lists each upstream source and points to Route 1 (per-OS user font folder), and the pick report says to check `typst fonts` first.
- Dependencies: `typst` is a compatible range `typst>=0.15.2,<0.16` in every PEP 723 header instead of the exact `typst==0.15.2` (the gates measure the real PDF on each run; a Typst minor is the breaking boundary); the doctor and the docs print the quoted range, and a unit test checks that every documented `pip install typst` uses the header's specifier.

## 0.12.1 - 2026-11-28

- `verify.py` runs one `typst query` per run instead of three: entry heads and sections come from the context query. A malformed section mark is now reported once in the `lib marks:` warning instead of also in a separate duplicate-names warning.
- `verify_academic.py` calls `pdfinfo` once per run instead of twice (it opens the run memo).
- Lint: ruff UP031 and UP032 (printf-style formatting becomes `str.format` / f-strings) and PLR0913 (at most 5 arguments) are enabled.
- Tests: the complexity tests count work deterministically (line events, characters scanned or copied, calls into C, structural regex checks) instead of timing it; no wall-clock assertion is left in `tests/unit`.

## 0.12.0 - 2026-11-27

- **Breaking:** invalid CLI values now exit 2 with a usage message instead of running on a nonsense value: `--ppi` outside 10..600, a page count outside 1..100, `--fill` outside 0..100, `--leading` outside 0.1..5.0. Input files past a size cap are refused before any work (`.typ` 4 MiB, PDF 16 MiB, TOML and facts files 1 MiB, PNG 32 MiB).
- **Breaking:** `verify.py` on an academic CV refuses with exit 2 and points to `verify_academic.py`, instead of grading it as a résumé.
- **Breaking:** compiled PDFs are PDF/UA-1 + PDF/A-2a conformant. - **Changed:** a tool that exceeds its timeout (typst, pdftotext, pdfinfo, pdftoppm, ...) is now a FAIL, never a WARN skip, and its whole process tree is killed; a tool that is missing stays a WARN. Every entry point fails cleanly on a hung tool.
